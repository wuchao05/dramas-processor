# 飞书评级优先级功能

## 功能说明

在飞书 watch 模式下，支持根据"评级"字段对同日期内的剧目进行优先级排序，确保高优先级剧目最先被处理。

## 使用场景

当同一天有多部待剪辑的剧时，可以通过在飞书表格中设置"评级"字段，让标记为"红标"的剧目优先处理。

## 排序规则

在 `feishu watch` 模式下，剧目的处理顺序遵循以下规则：

### 1️⃣ 日期层面（外层优先级）
- 🔴 **最高优先级**：已过期的日期（昨天、前天等） - 越早过期的越优先
- 🟡 **次优先级**：今天的日期
- 🟢 **最低优先级**：未来日期（明天、后天等） - 越近的越优先

### 2️⃣ 同日期内的剧目（内层排序）⭐ **新增功能**

#### 对于 xh-daily 用户（启用评级优先级）
1. **评级为"红标"的剧** → 最优先处理
2. **评级为"绿标"的剧** → 次优先
3. **评级为"黄标"的剧** → 再次优先
4. **无评级的剧** → 最后处理

在同评级内：
- ✅ **今天上架的剧** 优先于 **非今天上架的剧**
- ✅ 各自组内按上架时间**升序**排序（越早上架的越先处理）

#### 对于非 xh-daily 用户（如 lm）
不考虑评级，直接按上架时间排序：
- ✅ **今天上架的剧** 优先于 **非今天上架的剧**
- ✅ 各自组内按上架时间**升序**排序（越早上架的越先处理）
- ❌ 没有上架时间的剧排在最后

## 配置说明

在配置文件中添加了两个新字段：

```yaml
feishu:
  # ... 其他配置 ...
  rating_field_name: "评级"         # 评级字段名（可自定义）
  priority_rating_value: "红标"     # 高优先级评级值（可自定义）
  upload_time_sort_desc: true      # 上架时间排序方向（可自定义）
```

### 配置项说明

- **rating_field_name**: 飞书表格中评级字段的名称（默认为"评级"）
- **priority_rating_value**: 表示高优先级的评级值（默认为"红标"）
- **upload_time_sort_desc**: 上架时间排序方向
  - `true`（默认）：降序，越新的越先处理
  - `false`：升序，越早的越先处理（如 xh-daily 配置）

如果你的飞书表格使用不同的字段名或评级标记，可以在用户配置中修改这些值。

## 示例场景

假设今天是 1月13日，飞书表格中有以下待剪辑剧：

| 剧名 | 日期 | 评级 | 上架时间 | 上架日期 |
|------|------|------|----------|----------|
| 剧A | 1.12 | 红标 | 1.13 08:00 | 今天 |
| 剧B | 1.12 | - | 1.12 15:00 | 昨天 |
| 剧C | 1.13 | 红标 | 1.13 10:00 | 今天 |
| 剧D | 1.13 | - | 1.12 12:00 | 昨天 |
| 剧E | 1.13 | 黄标 | 1.13 09:00 | 今天 |
| 剧F | 1.14 | - | 1.13 16:00 | 今天 |

### 非 xh-daily 用户（如 lm）的处理顺序

**1.12（昨天）的剧**：
1. **剧B** (1.12 昨天 + 上架昨天15:00) → 昨天+非今天上架 🔴

**1.13（今天）的剧**：
1. **剧C** (1.13 今天 + 上架今天10:00) → 今天+今天上架（较晚）🟡
2. **剧E** (1.13 今天 + 上架今天09:00) → 今天+今天上架（较早）🟡
3. **剧D** (1.13 今天 + 上架昨天12:00) → 今天+非今天上架 🟡

**1.14（明天）的剧**：
1. **剧F** (1.14 明天 + 上架今天16:00) → 明天+今天上架 🟢

### xh-daily 用户的处理顺序（启用评级）

**1.12（昨天）的剧**：
1. **剧A** (1.12 昨天 + 红标 + 上架今天08:00) → 昨天+红标+今天上架 🔴
2. **剧B** (1.12 昨天 + 无评级 + 上架昨天15:00) → 昨天+无评级+非今天上架 🔴

**1.13（今天）的剧**：
1. **剧C** (1.13 今天 + 红标 + 上架今天10:00) → 今天+红标+今天上架 🟡
2. **剧E** (1.13 今天 + 黄标 + 上架今天09:00) → 今天+黄标+今天上架 🟡
3. **剧D** (1.13 今天 + 无评级 + 上架昨天12:00) → 今天+无评级+非今天上架 🟡

**1.14（明天）的剧**：
1. **剧F** (1.14 明天 + 无评级 + 上架今天16:00) → 明天+无评级+今天上架 🟢

## 配置文件位置

- 全局默认配置: `configs/default.yaml`
- 用户配置: `configs/users/xh-daily.yaml` (或其他用户配置)

## 技术实现

1. **feishu_client.py**: 在获取待剪辑剧信息时，额外获取"评级"字段
2. **feishu_watcher.py**: 在按日期分组后，对同日期内的剧按评级和上架时间排序
3. **models/feishu.py**: 添加配置项 `rating_field_name` 和 `priority_rating_value`

## 注意事项

- 该功能仅在 `feishu watch` 模式下生效
- 如果飞书表格中没有"评级"字段或该字段为空，不影响正常处理流程
- 可以通过修改配置自定义评级字段名和优先级标记值
